# 原理与实验

这份文档说明硅基保留为什么这样设计，以及支撑每个设计的实验数据。所有实验都在 2026 年 10 月做，用的是合成数据，评测规模不大；数字用来说明方向，不是定论。

## 1. 要解决的问题

在抖音等社区里，很多人用 DeepSeek 养长期陪伴的 AI 角色，反复遇到这些问题：

- **上下文满了，"她"就没了。** 开新窗口只能让新的 AI 读旧的聊天记录，用户的说法是"新鱼读旧鱼的日记"。
- **读来的记忆没有感受。** 知道发生过什么，但不知道当时是怎么相处的。
- **记忆越多越贵、越慢；压缩以后又会变笨、变陌生。**
- **想把"她"留在本地，又舍不得云端的大脑。** 本地能跑的小模型太弱。

## 2. 思路

| 部分 | 放在哪 | 管什么 |
|---|---|---|
| 说话方式、相处习惯 | 本地 2B 小模型的 LoRA 权重，每晚用当天的聊天继续训练 | "她是谁、怎么跟你说话" |
| 每一句聊天原文 | 本地硬盘，只追加，从不压缩 | "发生过什么" |
| 思考、知识、写东西 | DeepSeek API | 回答的内容和质量 |

LoRA 权重怎么影响 DeepSeek 的输出（logit 融合，参考 Proxy-Tuning）：
1. DeepSeek 流式输出，每个位置附带前 20 个候选及其概率。
2. 本地模型分别在开、关 LoRA 两种状态下给这些候选打分，两者的差 Δ 就是"她会更倾向说哪个"。
3. 融合分布 pF ∝ pDeepSeek · exp(α·Δ)。
4. 用投机采样的规则决定接受 DeepSeek 的 token，还是改写成融合分布里的另一个。
5. 改写后，从改写处让 DeepSeek 接着写（前缀续写）。

DeepSeek 看到的提示是：人格卡、当前时间、过去的概况，以及按你这句话检索出来的原文片段，总长固定，不随相处时间增长。

## 3. 关键实验

### 3.1 API 能力（阶段 0）

- DeepSeek 流式输出逐 token 返回前 20 个候选的概率。前 20 个候选平均覆盖 99.86% 的概率质量。
- `logit_bias` 会被静默忽略，所以前 20 名之外的词无法拉进来。这是"前 20 天花板"。
- 返回的概率是按 temperature 调整之后的，所以请求一律用 temperature=1。
- 每次改写要重新请求，DeepSeek 吐出第一个 token 约需 0.5 秒。这是速度的下限。
- 本地模型选 Qwen3.5-2B：它的切词和 DeepSeek 对齐最好，94% 的候选恰好对应一个本地 token；许可证是 Apache-2.0。

### 3.2 人格能不能烤进权重再传给 DeepSeek（阶段 1）

做法是 Prompt Baking：先让带人格卡的基座当老师，再训练不带人格卡的 LoRA 去模仿它，用全词表 KL 作为损失。65 条测试题由 DeepSeek-V4-Pro 盲评，满分 5：

| DeepSeek 看到的 | 人格分 | 内容质量 |
|---|---|---|
| 什么都没有 | 1.26 | 3.80 |
| 什么都没有，加融合 | 3.20 | 4.46 |
| 一句身份卡，加融合 | 4.17 | 4.69 |
| 完整人格卡（不融合） | 4.52 | 4.91 |

结论：权重确实能把人格传给 DeepSeek，内容质量不降，数学题成绩也没有显著下降。但对于写得出来的固定人格，直接把人格卡放进提示更好、更快。权重的价值必须来自提示做不到的事。

### 3.3 记忆怎么放（阶段 2，30 天，74 题）

| 做法（记忆都限制在约 1500 字） | 得分 | 说错（虚假记忆） | 最早 10 天的得分 |
|---|---|---|---|
| 滚动摘要 | 0.64 | 13.5% | **0.26** |
| 按原话检索原文 | 0.81 | 10.8% | 0.66 |
| **每周概况 + 检索原文** | **0.89** | **4.1%** | 0.74 |
| 时间观念写进权重，再按权重给的时间检索 | 0.83 | 9.5% | 0.79 |

结论：
- 不要压缩，原文加每周概况最好。
- 时间观念写进权重和检索打平，没有超过。
- 权重给出的日期可能出错，只能当线索，不能当硬过滤。

### 3.4 "她还是不是她"（阶段 3，90 天，50 题）

先合成 90 天的相处。其中有 19 种相处中长出来的说话方式（人格卡里没写，是聊着聊着才形成的）。然后在全新窗口里发一句话，看还认不认得出她。

由 Claude 盲评：每题下 7 组回答打乱、隐去组名，评分标准事先定好。

| 组 | 相处方式出现率 | 像不像她（1–5） | 编造 |
|---|---|---|---|
| 全新的 DeepSeek | 0.30 | 2.68 | 0% |
| 摘要 | 0.57 | 3.46 | 10% |
| 只检索 | 0.64 | 3.78 | 4% |
| 读完整日记（每轮约 6.7 万字） | 0.76 | 4.10 | 4% |
| 只靠权重 | 0.43 | 3.02 | 0% |
| **权重 + 检索**（提示约为完整日记的 1/36） | **0.80** | **4.08** | 10% |
| 本地 2B 单独回答 | 0.37 | 1.32 | 90%（自说自话） |

配对比较：权重 + 检索相对只检索，相处方式 +0.16、像不像她 +0.30，两项都显著。这两组发给 DeepSeek 的提示完全相同，差别只来自权重。

另一位评委 DeepSeek-V4-Pro 也认为相处方式的提升显著，但在"像不像她"上没看出显著差别，并认为权重 + 检索比读完整日记差 0.26。

结论：
- 只靠权重不够。原因是前 20 天花板：提示里没有相关原文时，那些专属说法根本不在候选里，权重挑不出来。
- 权重 + 检索：检索把原文放进上下文，候选里才会出现那些说法，权重再把它们挑出来。
- 本地 2B 不能单独回答。

### 3.5 长对话越聊越短

| | 回答字数（前 10 轮 → 第 31–40 轮） |
|---|---|
| 原来的融合 | 86 → 61 |
| 句末候选不加偏移 | 67 → 55 |
| 换成用聊天日志训练的 LoRA | 62 → 45 |

原因有两个：一是融合会不断给"结束回答"加分；二是 LoRA 学到的篇幅会把 DeepSeek 往同样的篇幅推。现在的处理办法：
- 句末不加偏移。
- 写东西、写代码这类任务降低人格强度。
- 夜间巩固时混入长回答作为篇幅锚。

篇幅锚的长期效果还没验证。

### 3.6 初版（阶段 4）

提速的办法是在 TV 很小的位置直接接受 DeepSeek 的词，并把改写集中在回答开头。三个速度档的实测（同一组 6 条闲聊 + 6 条任务）：

| 档 | 闲聊 | 任务 | 平均改写次数 |
|---|---|---|---|
| `fast` | 9.3 秒 | 8.9 秒 | 9.0 / 4.5 |
| `medium` | 11.5 秒 | 12.6 秒 | 12.3 / 9.5 |
| `strong`（严格投机采样） | 14.9 秒 | 18.5 秒 | 16.5 / 16.8 |

三档的第一个字都在约 1 秒出来。

用阶段 3 的 50 题盲评 `fast` 档：

| | 相处方式 | 像不像她 | 编造 |
|---|---|---|---|
| fast | 0.74 | 3.96 | 4% |

它和权重 + 检索（研究引擎）、读完整日记都打平（差别不显著）。比研究引擎略低的那部分，应该就是提速的代价。编造从 10% 降到 4%，是因为加了"看不到图片和附件就直说"之类的规则。

所以速度做成了可调的档位，默认 `medium`，取两者中间。`medium` 和 `strong` 的质量没有单独盲评。

### 3.7 情绪加权巩固（还没评测）

人对情绪强烈的事记得更牢：杏仁核给这类经历打上标记，睡眠时海马重放会优先巩固它们。夜间巩固照这个思路做：
- DeepSeek 读每天的聊天，给每一问一答定情绪强度：2 = 很强（吵架、崩溃、狂喜、人生大事），1 = 明显，0 = 日常的累、烦和闲聊。
- 抽样时强度 0 / 1 / 2 被抽中的相对机会是 1 / 2 / 4，新发言和旧日子回放都这样抽；强度 2 的当晚多学一遍。
- 标记存在 `data/memory/emotion.json`，一晚最多补 60 天，从近到远。

在合成数据上检查过标记（Claude 判读）：
- 提示里没写分级说明时，日常抱怨也被标成 1，5 天里一半的问答带标记；写上分级说明后，同样 5 天降到约三成。
- 7 天各标两次，6 天结果完全一样。强度 2 给的是和母亲吵架、惊喜生日这类时刻；边界上的句子偶尔会在 1 和 2、0 和 1 之间变。

它对权重的长期效果还没有评测。

## 4. 已知的局限

- **数据**：全部是合成数据（3 个月、轻度聊天），没有真实用户的长期数据。
- **评委**：盲评由 Claude 和 DeepSeek-V4-Pro 担任，两者相关系数只有 0.59。Claude 也参与了实验设计，对假设有预期。
- **规模**：一年以上没有测过。按结构推算：
  - 每轮提示固定，速度和费用不随时间增长。概况超过约 1200 字后，会把早期的周合并成月、月合并成年。
  - 检索在数据多几倍后还准不准，没测过。
  - 权重经过几百次巩固后会不会漂移，没测过。
  - 相对"读完整日记"，在它还装得下的时候，最多打平；装不下以后它只能退回压缩或检索。
- **依赖**：依赖 DeepSeek 继续提供前 20 个候选的概率。DeepSeek 换版本、换词表都不需要重训权重，因为本地模型是按候选的文字打分的。
