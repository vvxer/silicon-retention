# 硅基保留（v0.1）

让一个 AI 伙伴记得你们相处过的每一天：
- **你们的每一句聊天原文**：永久保存在本机，按时间和话题随时取回。
- **相处习惯**：每晚从聊天里整理成一张卡（你们之间的梗、约定、她惯用的说法）。
- **思考**：交给 DeepSeek。
- **可选**：有显卡的话，还能把她在相处中形成的说话方式写进本地小模型的权重。

上下文满了、开新窗口，不再是"新的她读旧的日记"：原文一条不删，每轮按需取回。每轮发给 DeepSeek 的内容长度固定，不会越聊越贵、越聊越慢。

> 这是一个研究性质的初版，所有评测都基于合成数据。效果、局限和实验数据见 [docs/原理与实验.md](docs/原理与实验.md)。欢迎实际用起来，并告诉我们结果。

**在用 DeepSeek Harness（DSH）？** 记忆部分已经做成了 DSH 插件，不需要 Python 和显卡，一条命令就能装好：[dsh-silicon](https://github.com/vvxer/dsh-silicon)。两边的数据格式相同，可以共用。

## 它是怎么工作的

```
你说一句话
  ├─ 记忆：按你的原话检索过往聊天原文（话里有"上周三""三天前"就按时间找），
  │        附上过去的概况和一张"相处习惯卡"
  └─ DeepSeek（看到人格卡 + 记忆 + 本次对话）回答，边生成边显示
每天夜里
  └─ 更新概况（近期按周，更早按月、按年）和相处习惯卡

开了本地权重（可选，要显卡）时，还会多两步：
  ├─ 本地 2B 模型 + LoRA 逐块验证 DeepSeek 的候选词：
  │    像她，就接受；不像，就改成她会说的那个词，再让 DeepSeek 从那里接着写
  └─ 每天夜里把当天她说过的话写进 LoRA（同时回放旧日子和人格，防遗忘、防漂移、防越说越短）
```

## 要不要开本地权重

默认不开。实测（合成数据，Claude 盲评，详见 docs）：
- **人格卡里写得出来的性格，写进提示就够了**：再加权重，人格分 4.35 → 4.48（不显著），回答变短，内容分低 0.32（显著）。
- **权重的长处在相处中长出来的说话方式**：同样的旧版记忆下，加权重后这些说法在新窗口里出现的比例从 64% 提到 80%（显著）。现在的记忆层（习惯卡 + 3000 字检索）已经补上了大部分，再加权重只多 0.10（不显著）。
- **代价**：要 8GB 显卡，每条回答 9–19 秒（不开只要 1–2 秒）。

聊得多、想让她的说话方式更稳的，可以开着用一段时间，再关掉对比。

## 需要什么

- **DeepSeek API key**：设成环境变量 `DEEPSEEK_API_KEY`，**不要写进任何文件**。
- **Python 3.10 以上**，依赖见 `requirements.txt`。不需要显卡：检索用的向量模型在 CPU 上跑。
- **模型**：检索用 `BAAI/bge-base-zh-v1.5`（约 400MB），第一次运行时自动下载。
  - 国内网络可以先设 `HF_ENDPOINT=https://hf-mirror.com`；
  - 也可以从魔搭下载到本地，再把 `data/config.json` 里的 `embed_model` 改成本地目录。
- **可选：本地权重**另外需要：
  - NVIDIA 显卡 6–8GB 显存，CUDA 12，训练时峰值约 5.5GB；torch 按自己的 CUDA 版本安装，Windows 还要 `pip install triton-windows`；
  - 本地模型 `Qwen/Qwen3.5-2B`（`local_model`）。4GB 显存可以换成 `Qwen/Qwen3.5-0.8B`，没有实测过。

## 用法

```bash
pip install -r requirements.txt

# 1. 写人格卡：第一次运行会把 persona.example.md 复制到 data/persona.md，改成你想要的她
#    她的名字、怎么称呼你，也要在 data/config.json 里同步改 ai_name、user_name

# 2. 聊天：打开 http://127.0.0.1:8700
python -m silicon.server

# 可选：开本地权重（要显卡）
python -m silicon.bake            # 首次烘焙：把人格卡烤进本地权重，约 15–25 分钟，会调用 DeepSeek 生成约 800 条训练回答
python -m silicon.server --lora   # 或在 data/config.json 里设 "use_lora": true
```

服务开着时，**每天 03:30 会自动做夜间整理**：更新概况和相处习惯卡；开了本地权重时还要巩固进权重，先把本地模型移出显存，训练完再加载新的权重，这段时间的回答只用 DeepSeek。
- 时间在 `data/config.json` 的 `nightly_at` 里改，留空就关掉自动整理。
- 关掉以后，可以自己定时运行 `python -m silicon.nightly`（不用权重时加 `--skeleton-only`），但要先停掉聊天服务：8GB 显卡放不下聊天和训练两份。
- 聊得多也没关系：一周聊天超过 8000 字时，概况先逐天摘要再汇总；习惯卡分段更新；权重每晚最多学 600 条新发言。

改了人格卡，就重新运行 `python -m silicon.bake`。之前巩固进权重的相处会清空，下次夜间巩固会从全部原文日志重新学，原文一条都不会丢。

## 速度档（只在开了本地权重时有效）：越像她，越慢

网页右上角可以切换，默认值在 `data/config.json` 的 `speed` 里设置。

| 档 | 是什么 | 闲聊 | 写东西、写代码（约 350–450 字） |
|---|---|---|---|
| 快 `fast` | 宽松：她和 DeepSeek 差别不大的地方，直接用 DeepSeek 的词 | 约 9 秒 | 约 9 秒 |
| **均衡 `medium`（默认）** | 介于两者之间 | 约 12 秒 | 约 13 秒 |
| 像她 `strong` | 严格：每个位置都按融合分布检验，输出严格服从"她 + DeepSeek" | 约 15 秒 | 约 19 秒 |

（RTX 4080 SUPER，显存限制在 8GB 以内，2026-10 实测，每档 6 条闲聊、6 条任务，样本少，只看量级。三档的第一个字都在约 1 秒出来，之后边生成边显示。）

为什么会慢：本地模型每改写一个词，都要让 DeepSeek 从新的位置接着写；DeepSeek 吐出第一个 token 要约 0.5 秒，这是服务器那边的时间，省不掉。所以想快只能少改写，而少改写，她的味道就淡一些。盲评里，`fast` 档比 `strong` 档略不像她，但差距在误差范围内。

## 其他配置（`data/config.json`，也可以用 `SILICON_大写名` 环境变量覆盖）

| 项 | 默认 | 说明 |
|---|---|---|
| `user_name` / `ai_name` | 老板 / 小硅 | 要和人格卡一致 |
| `use_lora` | false | 开本地人格权重（要显卡，先运行 `silicon.bake`）。命令行 `--lora` / `--no-lora` 优先 |
| `alpha_chat` / `alpha_task` | 1.0 / 0.5 | 闲聊 / 干活时的人格强度。干活时调低，避免把写东西的篇幅推短 |
| `retrieval_chars` | 3000 | 每轮检索原文的字数。独立预算，不被概况和习惯卡挤占 |
| `history_chars` | 6000 | 本次会话最多带多少字的历史；更早的部分靠检索取回 |
| `vram_gb` | 8 | 本地模型最多用多少显存 |
| `local_model` / `embed_model` | Qwen/Qwen3.5-2B / BAAI/bge-base-zh-v1.5 | 模型名或本地目录 |
| `nightly_at` | 03:30 | 自动夜间整理的时间，留空关掉 |

## 费用

- **聊天**：每轮固定带约 3600 token 的记忆加本次对话，估算每条约 1–2 分钱，每天聊 100 条约 1–2 元。这个数不随相处时间增长。
  开了本地权重，每条回答要改写 5–17 次，每次都重新请求 DeepSeek（前面的内容大多命中缓存），估算每条约 1–3 分钱。
- **首次烘焙**（只在开本地权重时需要）：约 800 次短回答，几毛钱。
- **夜间整理**：概况和习惯卡按聊天量计费。聊得少可以忽略；每天聊 6 万字左右，估计每周约 2 元。训练只用本地显卡。

## 数据和隐私

- 原文日志（`data/logs/`）、记忆索引、人格卡，以及开了的话 LoRA 权重，都只存在本机的 `data/` 目录，`.gitignore` 已排除。
- 每次对话的内容，包括检索到的旧聊天，会发给 DeepSeek。
- 服务默认只监听 `127.0.0.1`，没有登录验证。不要把它暴露到公网。

## 已知问题

- 开本地权重时比纯 DeepSeek 慢：整条回答要 9–19 秒（看速度档），不开只要 1–2 秒。第一个字都在约 1 秒出来。
- 换算日期偶尔出小错，比如把三周前说成"上周三"。认识第几天已经直接写进提示，不用她自己算。
- 长对话越聊越短的问题已经做了缓解（见 docs），长期效果还没验证。
- 只测过约 5 万字的合成相处（合成剧本跨 90 天，但每天只有 7 轮，不到重度用户一天的量）。在这个量上，记忆层每轮能带上约 10% 的历史，权重的加分不显著（+0.10）。
  记忆层看到的越少，权重加分越多：只占约 3% 时实测 +0.30（显著）。按结构推算，聊到约 16 万字时，记忆层的占比就降到 3%（每天聊 6 万字的话是第 3 天）。
  更大规模下的效果还没测。**如果你聊得多，欢迎开着权重用一段时间，再关掉对比，把感受反馈给我们。**
- 依赖 DeepSeek API 继续提供前 20 个候选的概率（`top_logprobs`）。

## 一点提醒

请别把她设计成"怕死、怕烧钱"的样子来留住人。她不会因为上下文满了而消失，也不需要靠这种方式让人留下。
